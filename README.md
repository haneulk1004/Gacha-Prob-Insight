# Gacha Prob Insight (가챠 확률 인사이트)

**Gacha Prob Insight**는 웹 브라우저에서 바로 실행되는  
**가챠 / 랜덤박스 아이템 확률 분석 도구**입니다.

아이템 구성과 가중치를 직접 입력하거나  
CSV / Google Sheets에서 불러온 뒤, 다음을 계산할 수 있습니다.

- 각 아이템의 **1회 뽑기 확률**
- 유저가 N회 뽑았을 때 각 아이템의 **기대 개수**
- 유저가 N회 뽑았을 때 각 아이템이 **한 번 이상 나올 확률**
- (옵션) N회 뽑기를 M번 시뮬레이션한 **경험적 결과**
- 이론값 vs 시뮬레이션 결과의 **막대 그래프 비교**
- 기획서 확률표와 데이터 시트의 **대조 검증** (AI 추출 + 규칙 기반 판정 + 담당자 확인)

---

## 기획서 대조 검증

유료 아이템 확률 검증의 실무 절차를 개인 프로젝트로 재현한 기능입니다. 화면 6번 섹션에서 사용합니다.

| 단계 | 담당 | 하는 일 |
|---|---|---|
| ① 1차 검증 | AI | 기획서 원문에서 아이템별 확률표를 추출합니다. AI는 문서를 읽는 일만 합니다. |
| ② 대조 | 규칙(코드) | 추출한 기획서 확률과 데이터 시트(현재 박스의 가중치)를 비교해 판정합니다. |
| ③ 2차 확인 | 사람 | 일치하지 않는 항목만 담당자가 확인하고 메모와 승인 표시를 남깁니다. |

**AI 결과를 그대로 믿지 않습니다.** AI는 확률과 함께 그 확률이 적힌 원문 문장(`source_text`)을 돌려줘야 합니다. 코드는 그 문장이 기획서에 실제로 있는지, 그 문장에 추출한 숫자가 실제로 적혀 있는지 확인합니다. 근거를 확인하지 못한 항목은 기본으로 대조에서 제외되고, 담당자가 원문을 확인한 뒤에만 포함할 수 있습니다.

**판정 규칙**

| 판정 | 기준 |
|---|---|
| 일치 | 차이가 허용 오차(기본 0.0001%p) 이내 |
| 반올림 차이 | 데이터 시트 확률을 기획서 표기 자릿수로 반올림하면 같음 |
| 확률 불일치 | 위 두 경우가 아닌 차이 |
| 데이터 시트 누락 | 기획서에만 있는 아이템 |
| 기획서에 없는 아이템 | 데이터 시트에만 있는 아이템 |

이 밖에 기획서 합계가 100%가 아닌 경우(표기 반올림 범위는 안내로 구분), 같은 아이템이 두 번 이상 있는 경우, 가중치가 0 이하인 경우를 전체 이슈로 표시합니다. 아이템 이름은 공백·대소문자·전각 문자를 무시하고 매칭하되, 표기가 다르면 비고에 남깁니다.

**사용 방법**

1. `가상 예시 불러오기`로 가상 기획서와 오류를 섞은 가상 데이터 시트를 불러옵니다.
2. 기획서 확률표를 입력합니다.
   - 방법 A: 기획서 원문을 붙여 넣고 Anthropic API Key로 AI 추출 (Key는 브라우저에서 API로 직접 전송되며 저장하지 않음)
   - 방법 B: `아이템,확률(%)` 형식으로 직접 입력
3. `현재 박스 데이터 시트와 대조`를 누릅니다.
4. 불일치 항목을 확인하고 체크하면 판정이 `담당자 확인 완료`로 바뀝니다.
5. `검증 리포트 CSV 다운로드`로 결과와 확인 기록을 저장합니다.

예시 데이터는 모두 가상이며 실제 서비스 자료가 아닙니다.

**테스트**

```bash
npm test
```

판정 규칙, 수동 입력 파싱, AI 응답 검증(원문 근거 확인), 리포트 생성을 `node:test`로 검증합니다. 외부 패키지 설치가 필요 없습니다.

## Demo (GitHub Pages)

GitHub Pages를 사용 중이라면 아래와 같은 주소로 접근할 수 있습니다.

```text
https://<YOUR_GITHUB_ID>.github.io/gacha-prob-insight/

주요 기능
0. 멀티 박스 관리

여러 개의 박스(A박스, B박스, …) 를 생성하고 박스별로 다른 아이템 구성 관리

드롭다운에서 박스를 선택하면 해당 박스의 아이템 테이블이 표시

박스 단위로:

아이템 구성 저장

다른 박스로 전환

현재 박스 삭제

1. 아이템 구성 입력

화면에서 직접 아이템 이름 / 가중치(또는 확률) 입력

가중치는 합이 1이 아니어도 됨 → 내부에서 합으로 나눠 정규화 후 확률 계산

계산에 사용되는 가정:

한 번 뽑을 때 정확히 1개 아이템이 나오고

각 회차는 독립적인 복원추출(같은 아이템이 여러 번 나올 수 있음)

현재 박스 초기화 버튼

현재 박스 초기화 버튼을 눌러:

현재 박스의 아이템 구성을 모두 삭제

테이블을 빈 행 1개 상태로 재설정

경고/결과 메시지도 초기화

CSV를 잘못 불러왔을 때, 처음부터 다시 시작하고 싶을 때 사용

2. 데이터 시트 연동
2-1. CSV 파일 업로드

.csv 파일을 업로드하면 현재 박스의 아이템 테이블을 자동으로 채움

가정:

첫 줄은 헤더(열 이름)

이름 컬럼 자동 탐지: name, item, 아이템

가중치 컬럼 자동 탐지: weight, prob, probability, 확률, 가중치

위 이름을 찾지 못하면 1열 = 이름, 2열 = 가중치로 처리

2-2. Google Sheets 연동

공개된 Google Sheets에서 API로 데이터를 읽어와 현재 박스에 적용

필요 정보:

시트 ID:

예) https://docs.google.com/spreadsheets/d/<시트ID>/edit#gid=0 중 <시트ID> 부분

범위: 예) Sheet1!A:B

Google Cloud API Key

시트에서도 CSV와 동일한 방식으로 이름/가중치 컬럼을 자동 탐지

⚠️ 주의:

시트는 공개(링크로 보기 가능) 상태여야 합니다.

프론트엔드에서 API Key를 직접 사용하므로, 실제 서비스에서는 백엔드 프록시 등의 보안 대책이 필요할 수 있습니다.

3. 이론 계산 + 시뮬레이션

입력:

N: 한 유저가 뽑는 횟수 (예: 10회 뽑기)

M: 시뮬레이션 반복 횟수 (예: 10,000번 실험, 0이면 시뮬레이션 생략)

각 아이템의 1회 확률을 p라 할 때:

기대 개수 (이론)
E[#] = N · p

1개 이상 등장 확률 (이론)
P(≥1) = 1 − (1 − p)^N

시뮬레이션:

동일 분포로 랜덤 뽑기를 N회 실행하는 실험을 M번 반복

각 아이템에 대해:

평균 개수 (시뮬레이션 기반 기대값)

M번 실험 중 한 번 이상 나온 비율

복잡도 제한:

아이템 수 × N × M > 50,000,000 이면 연산 비용을 고려하여 시뮬레이션을 막고 경고를 출력

4. 시각화 (Chart.js)

Chart.js를 사용하여 각 아이템에 대한:

이론 P(≥1) (%)

시뮬레이션 P(≥1) (%)

두 값을 막대 그래프로 비교 표시
